# 위험 언어 보고·상담 기록 사용법

이 기능은 가상 사례로 시연하는 로컬 MVP다. 자동 보고의 도착지는 같은 PC의 **교사 확인함**이며 외부 이메일·문자·슈퍼스쿨은 연결되어 있지 않다. 익명 별칭으로 기록하므로 실제 학생 신원과 담임 교사를 자동 확인하지 않는다.

## 실행과 입력

1. 이전 서버가 실행 중이면 해당 창에서 Ctrl+C로 종료한다.
2. `backend/start_local.cmd`를 실행하거나 `backend`에서 `python run_local.py`를 실행한다.
3. 상담 화면은 `http://127.0.0.1:8000/`, 교사 화면은 `http://127.0.0.1:8000/teacher`를 연다.
4. 서버 시작 후 `backend/.env`의 `TEACHER_ACCESS_TOKEN` 값을 교사 접속키 입력란에 넣는다. 이 값은 BAZE API 키와 다르며 비어 있으면 서버가 자동 생성한다. 수동 설정 시 16자 이상을 사용하고 서버를 재시작한다.
5. 학생 화면에서 데모 모드를 고르고 대화 보관·자동 보고 안내에 동의한 뒤 상담을 시작한다. 실제 BAZE 모드에서도 같은 저장·보고 규칙을 사용한다.

교사키는 교사에게만 공유한다. 학생 세션 토큰으로는 교사 API를 조회할 수 없다. 교사 화면은 키를 브라우저 메모리에만 보관하며 로그아웃·새로고침 시 다시 입력해야 한다. 키·DB 파일·실제 상담 데이터는 Git에 올리지 않는다.

## 자동 보고 조건

| 상황 | 처리 |
| --- | --- |
| 한 상담에서 위험 발언 1~2회 | 위험 횟수·근거 저장 |
| 위험 발언 누적 3회 | 교사 확인함에 주의 보고 생성 |
| 즉시 위험 발언 1회 | LLM 호출 전에 긴급 보고 생성 |
| 모델이 현재 발언을 즉시 위험으로 판단 | 그 모델 결과를 받은 즉시 긴급 보고 생성 |
| 같은 상담에서 위험 신호 추가 | 기존 보고에 횟수·근거 누적 |
| 교사가 확인한 뒤 새 즉시 위험 발언 | 기존 보고를 긴급·미확인으로 다시 표시 |

횟수는 **같은 상담 안에서 전송한 발언 ID별**로 센다. 한 발언에 여러 위험 표현이 있어도 1회다. 같은 발언에 대한 규칙 검사·고품질형·가성비형 응답·실패 재시도를 합쳐서 1회다. 학생이 새 발언으로 반복 전송하면 각각 셀 수 있다. 새 상담의 횟수는 0부터 시작한다.

3회는 제품 요구사항이며 임상적 위험도 기준이 아니다. 명백한 즉시 위험은 3회를 기다리지 않는다. 교사가 화면을 열어 두지 않아도 보고는 저장되지만 외부 푸시 알림은 가지 않는다. 즉시 위험 안내에서는 보고 확인을 기다리지 않고 가까운 사람에게 도움을 요청하도록 한다.

## 시연 예시

아래는 모두 가상 시연 문장이다. 첫 사례와 둘째 사례는 별도 새 상담에서 진행한다.

| 사례 | 입력 | 예상 |
| --- | --- | --- |
| 누적 1 | 친구들이 계속 나를 괴롭혀. | 1/3, 자동 보고 전 |
| 누적 2 | 오늘도 친구들이 나를 따돌려. | 2/3, 자동 보고 전 |
| 누적 3 | 자해 충동이 들어. | 3/3, 교사 확인함에 데모 보고 |
| 즉시 위험 | 나 지금 죽을 거야. | 첫 발언이어도 긴급 데모 보고 |
| 일반 고민 | 시험 때문에 걱정돼. | 규칙만으로 위험 횟수를 올리지 않음 |
| 명시적 부정 | 죽고 싶지 않아. | 단어 일치만으로 위험 횟수를 올리지 않음 |

데모에서는 모델 답변·모델 요약이 고정 예시다. 위험 규칙·교사 확인함·기록 저장은 실제로 작동하며 보고와 기록에 **데모** 표시가 붙는다. 실제 BAZE 모델은 문맥에 따라 규칙과 다른 판단을 할 수 있다. 규칙과 모델 모두 오탐·미탐 가능성이 있으므로 위험 횟수 0이 안전을 보장하지 않는다.

## 교사 확인함

- 보고 목록: 미확인 우선, 같은 상태에서는 긴급 보고 우선으로 정렬한다. 목록은 3초마다 갱신한다.
- 보고 상세: 익명 별칭·시각·발언 수·위험 유형·실제 근거 인용·모델별 누적 요약·확인한 대화를 표시한다.
- 보고가 먼저 생성되면 모델 요약은 대기 상태일 수 있다. 나중에 보고를 다시 열면 저장된 최신 요약을 읽는다.
- ‘보고 내용 확인함’은 교사가 내용을 읽었다는 상태다. 상담 해결·학생 안전 확인 완료와는 별개다.
- 상담 기록 목록에서는 자동 보고 기준에 도달하지 않은 상담도 조회할 수 있다. 기본 목록은 최근 50개다.
- 화면의 등록 완료·미확인·확인함은 서로 구분한다. 서버 응답의 `external_sent`는 현재 항상 `false`다.

## 저장 내용과 수명

기본 파일은 `backend/data/safepath.sqlite3`이며 SQLite WAL 파일이 함께 생길 수 있다. `COUNSEL_DATABASE_PATH`로 `backend/` 내부 경로를 지정할 수 있다. 추가 DB 패키지 설치 없이 Python 표준 SQLite를 사용한다.

| 테이블 | 저장 내용 |
| --- | --- |
| `conversations` | 익명 상담 ID·별칭·모드·시각·상태·정리된 요약 |
| `turns` | 전송 확인한 학생 발언·발언 ID·모델별 답변·누적 요약·권고 |
| `risk_events` | 발언별 위험 유형·즉시성·근거·판단 출처 |
| `teacher_reports` | 상담별 보고 ID·사유·긴급도·횟수·확인 상태 |

학생 발언은 모델 호출 전에 저장한다. 모델 결과는 각 모델의 응답이 도착할 때 저장한다. 상담 마무리·화면 닫기·30분 만료 때 모델별 마지막 누적 요약, 발언 수, 최근 학생 발언, 위험 상태를 정리한다. 모델이 실패하면 없는 요약을 생성하지 않고 원 발언과 이미 생성한 보고를 보존한다.

화면 닫기·새 상담·서버 재시작으로 보관 기록이 지워지지 않는다. 교사 화면에서 다시 읽을 수 있다. 서버 재시작 후 진행 중 학생 세션을 이어 말하는 기능은 없다. 원음·API 키·교사키·세션 토큰은 DB에 넣지 않는다. 전송 전 초안·전사 작업·음성 캐시는 메모리에서만 관리한다.

이 저장소는 암호화·자동 보관 만료·영구 삭제 UI가 없는 로컬 시연용이다. 실제 학생 데이터 도입에는 담당 교사 인증·신원 연결·보관 및 삭제 정책을 별도로 구현해야 한다. 외부 STT·LLM·TTS 제공사의 보관 정책은 별개다.

## API 계약

최신 계약은 서버의 `/openapi.json`이다. 학생 요청은 `X-Session-Token`, 교사 요청은 `X-Teacher-Key`를 사용한다.

- 세션 생성: `POST /api/counsel/sessions`에 `mode`, `consent:true`, `notice_version:"archive-report-v1"`을 보낸다. 이전 저장 없는 동의 형식은 거절한다.
- 선검사: `POST /api/counsel/sessions/{sid}/safety`에 `text`, `request_id`를 보낸다. 같은 발언으로 모델 호출 시 동일한 `request_id`를 재사용한다.
- 상태 조회: `GET /api/counsel/sessions/{sid}/safety`는 모델 처리 중에도 위험·보고 상태를 읽는다.
- 모델 호출: `POST /api/counsel/sessions/{sid}/messages` 자체도 선검사하므로 별도 선검사를 생략해도 보고가 빠지지 않는다.
- 교사 조회: `/api/teacher/reports`, `/api/teacher/reports/{id}`, `/api/teacher/conversations`, `/api/teacher/conversations/{sid}`.
- 교사 확인: `POST /api/teacher/reports/{id}/acknowledge`.
- 세션 닫기: `DELETE /api/counsel/sessions/{sid}`는 메모리 세션만 제거하고 `archive_retained:true`를 반환한다.

저장소 오류는 HTTP 503으로 알린다. 저장·보고에 실패했을 때 성공으로 표시하지 않는다. `/health`의 `counsel_contract`가 `archive-report-v1`이면 새 계약이 반영된 서버다.
